## Reflection

### 1. What went well during this unit?

We completed the HabitFlow planning documents, presented the project pitch,
created the GitHub project board, and created the required feature issues.
The feedback confirmed that measuring habit consistency and progress should
remain central to the project.

### 2. What were some challenges your group faced in this unit?

The main challenge was learning how GitHub Projects, repository issues, and
GitHub milestones work together. We also had to keep the scope realistic, so
we decided to prioritize the required full-stack features before optional
authentication or real AI integration.

### Did you finish all of your tasks in your sprint plan for this week? If you did not finish all of the planned tasks, how would you prioritize the remaining tasks on your list?

We completed the planning, pitch, project board, issue creation, and issue
status tasks planned for this unit. The application implementation remains for
the next sprint. We will prioritize the PostgreSQL schema and task REST API
because the frontend depends on a working backend.

### Which features and user stories would you consider “at risk”? How will you change your plan if those items remain “at risk”?

Real AI-generated insights and GitHub OAuth are at risk because they require
external services and additional deployment configuration. If time becomes
limited, we will defer those stretch features and prioritize task CRUD, habit
tracking, database relationships, validation, filtering, error handling, and
deployment.

### 5. What additional support will you need in upcoming units as you continue to work on your final project?

We will need support connecting PostgreSQL to Express, implementing and testing
the REST API, connecting the React frontend to the backend, and deploying the
completed application to Render.
